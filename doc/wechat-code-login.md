# 微信验证码登录：接入、验证与维护

本文说明 FmlySys 的公众号验证码登录如何接入、运行和排障，并记录未认证个人订阅号通过手工菜单回调识别点击者的可行路径与限制。

## 登录流程

用户从 FmlySys 登录页打开“微信验证码登录”后，服务端为这次浏览器登录生成随机状态和场景值，向公众号申请一个十分钟有效的临时二维码。扫码产生的 `subscribe` 或 `SCAN` 事件把公众号 OpenID 绑定到这次浏览器尝试。用户在公众号发送“登录”后，公众号回复一个八位数字验证码；用户在原浏览器输入验证码后，服务端才签发成员会话。

验证码五分钟有效，只能使用一次，只能兑换扫码时对应的浏览器状态；错误尝试达到五次后，该次登录失效。二维码过期、验证码过期、频率限制或成员身份未绑定时，用户需要按页面提示重新开始。该流程不会自动创建、审批成员，也不会绕过已有的成员权限。

公众号回调的 `FromUserName` 是该公众号下的 OpenID。它不一定与网站微信应用的 OpenID 相同。FmlySys 会尽量通过 UnionID 匹配已审核成员；公众号与网站微信应用通常需要绑定到同一个微信开放平台账号，才能拿到可跨应用匹配的 UnionID。若没有 UnionID，系统只接受完全相同的 OpenID。没有可匹配的已绑定成员时，登录会被拒绝。

## 新接入

### 1. 准备公众号与站点

需要能调用公众号接口的 AppID 和 AppSecret，以及一个可从公网访问的 FmlySys HTTPS 域名。AppSecret 必须只保存在服务器端。若公众号平台要求配置 API 调用 IP 白名单，还需加入 FmlySys 出站公网 IP。

确认站点反向代理保留正确的 Host 和 HTTPS 协议信息，公众号才能访问正确的回调地址。仅有 `localhost`、内网地址或自签 HTTPS 的部署不能接收公众号服务器回调。

### 2. 设置 FmlySys 环境变量

在服务器的 `data/config.env` 中配置：

```dotenv
FMLYSYS_WECHAT_OA_APP_ID=公众号AppID
FMLYSYS_WECHAT_OA_APP_SECRET=公众号AppSecret
FMLYSYS_WECHAT_OA_TOKEN=自行生成的随机字符串
```

`FMLYSYS_WECHAT_OA_TOKEN` 是回调签名用的 Token，不是 `EncodingAESKey`。按当前程序校验规则，它需要是 16–32 个可见 ASCII 字符。生成随机值，并在公众号后台 Token 栏与此配置中填写同一个值。不要把实际密钥写进 Git、工单或聊天记录。

修改配置后重启 FmlySys。登录页出现“微信验证码登录”入口且后台“开发中心”显示配置完整，表示必要配置已加载；它并不代表公众号 API 权限和回调联通性已经验证。

### 3. 配置公众号消息推送

在公众号后台的“配置消息推送”或相应服务器配置页面填写：

| 字段 | 设置 |
| --- | --- |
| URL | `https://你的公网域名/auth/wechat/code/callback` |
| Token | 与 `FMLYSYS_WECHAT_OA_TOKEN` 完全相同 |
| 消息加密方式 | 明文模式 |
| 数据格式 | XML |
| EncodingAESKey | 后台要求时随机生成并保留；明文模式下当前程序不使用它 |

当前回调实现校验 `signature`，并直接解析和回复明文 XML，没有实现 `EncodingAESKey` 的加解密。不要选择安全模式或兼容模式。该公众号消息推送 URL 通常是公众号唯一的接收地址；若已有其他业务回调，需要把业务统一转发到一个入口或在同一个回调处理器中分流，不能让两个系统分别占用公众号配置。

保存后由公众号后台验证服务器配置。验证失败时先确认服务公网可达、HTTPS 证书有效、路径无误、Token 完全一致、服务已重启并且反向代理未改写请求。签名错误会被拒绝，不会进入开发中心的有效事件列表。

## 日常使用与身份绑定

1. 用户访问 `/login/wechat-code`，页面为当前浏览器申请临时二维码。
2. 用户使用要登录的微信扫描二维码；关注事件或已关注用户的扫码事件把其公众号 OpenID 与这次网页尝试绑定。
3. 用户在公众号发送“登录”，收到验证码后回到原网页输入。
4. FmlySys 一次性消费浏览器绑定的验证码，并将公众号身份映射到已审核成员；映射成功才创建 `fmly_session`。

如果首次登录显示身份未绑定，先通过项目现有微信身份审核/绑定流程建立成员关联。不能仅凭昵称、菜单参数或用户自行提交的 OpenID 自动认定成员身份。

## 用开发中心验证手工菜单回调

即使个人未认证订阅号不能用自身 AppID/Secret 调用菜单创建接口，管理员后台仍可手工创建菜单。FmlySys 在 `/admin/developer` 增加了一个只读探针：公众号回调收到并通过 Token 签名校验的事件会临时记录在内存中，页面每三秒更新一次。探针最多保留最近 50 条，服务重启后清空；只对管理员开放，显示 OpenID 和菜单 URL，不保存普通消息正文。

验证步骤：

1. 先完成上面的公众号服务器 URL、Token、明文模式和 XML 配置，并登录 FmlySys 管理后台。
2. 打开“开发中心”，确认配置状态完整。
3. 在公众号后台手工创建“跳转网页”菜单，目标设为 `https://你的公网域名/healthz?source=wechat-menu-view-test`。其中 `/healthz` 是 FmlySys 健康检查地址；请替换成真实公网 HTTPS 域名。
4. 保存并发布菜单，等待菜单更新生效。用一个关注者微信打开公众号会话并点击该菜单。
5. 回到开发中心查看事件列表。

若出现 `VIEW` 事件，事件行中的 `FromUserName` 是此次点击者的公众号 OpenID，`EventKey` 是菜单设置的目标 URL。这证明“手工菜单跳转 + 公众号消息回调”能让服务端获知点击者身份。若没有事件，先确认菜单已发布且等待更新，再检查公众号消息推送配置与服务日志；开发中心只展示通过签名校验的事件。

微信的[自定义菜单事件推送说明](https://developers.weixin.qq.com/doc/offiaccount/Custom_Menus/Custom_Menu_Push_Events.html)还列出了 `VIEW` 事件字段。事件本身提供 OpenID 和菜单 URL，不包含用户昵称等资料。服务端如需资料，可在权限允许且用户满足平台条件时，以该 OpenID 调用公众号用户信息接口；跨应用关联应优先使用 UnionID，不能把昵称当作身份凭证。

当前公众号客户端通过 `/cgi-bin/user/info` 查询用户信息，但只读取并使用 OpenID 和 UnionID，不读取昵称等资料。读取更多字段需要扩展客户端响应结构，并确认公众号接口权限和用户关注状态满足微信平台要求。

### 未认证个人公众号的菜单登录曲线方案

菜单的网页地址是静态配置。可以带 `?source=wechat-menu` 这类固定来源标记，但所有人拿到的值一样，微信不会把点击者 OpenID 自动附加到浏览器的 URL 参数中。菜单跳转的浏览器 GET 与发给 FmlySys 的 `VIEW` 事件是两条独立请求：后者才包含 `FromUserName`。不要按“最近一次点击”或时间窗口把不同请求强行配对，多人同时点击时会串号。

如果开发中心确认当前账号确实发送 `VIEW`，可以在后续版本实现安全的菜单登录：回调收到事件后取 OpenID，匹配已绑定成员，生成短时、单次、与该 OpenID 绑定的随机登录票据，再通过公众号回复给用户；用户点击或输入该凭证完成网页登录。这样身份随回调获得，票据负责安全地带到浏览器，不依赖把 OpenID 暴露在 URL 中。短数字码也可以作为备选，但必须限时、限次、限一次使用，并绑定用户身份。

这条登录方案目前**尚未实现**；现有回调只把 `VIEW` 事件显示在开发中心，不会因此登录用户或发送登录票据。上线前还要验证该账号的手工菜单确实产生 `VIEW`、公众号可以按预期回复消息、该 OpenID 能映射到 FmlySys 成员，并为一次性票据增加防重放和失败限流。当前微信内置浏览器保护也会拦截普通功能页，若以后要让菜单内完成登录，应只为一次性票据兑换端点开放必要访问，不能整体关闭保护。

如果没有 `VIEW` 事件，或者无法满足 OpenID 绑定和安全票据要求，就继续使用已有二维码验证码登录；其他选择是使用具备相应接口权限的账号，或通过正式授权的微信第三方平台集成。不要用伪造 OpenID、未签名参数或可复用静态 URL 代替身份验证。

## 维护与排障

- **配置不完整**：检查三个 `FMLYSYS_WECHAT_OA_*` 变量是否在运行进程实际加载的 `data/config.env` 中；Token 长度须为 16–32 个可见 ASCII 字符。配置变更后重启进程。
- **线上 Cloudflare 返回 502 Bad Gateway**：这不是登录页给出的业务错误。先检查 Cloudflare 到源站的连接、源站进程是否运行、反向代理 upstream 地址/端口及源站日志；同时在源站本机和公网分别请求 `/healthz`，区分源站故障和 Cloudflare/代理路径故障。
- **测试环境返回 `Cannot GET /login/wechat-code`**：当前 Go 版本在主路由注册了 `GET /login/wechat-code`。即使微信验证码登录配置缺失，该处理器也应返回说明配置缺失的 HTML（HTTP 503），而不是 `Cannot GET`。出现该文本通常表示请求到达了旧版本、另一套 Express/静态服务，或反向代理没有把该路径转给当前 Go 服务；确认目标环境部署了包含该路由的版本，并检查路径路由规则。
- **微信内打开登录页**：当前版本的微信内置浏览器保护会拦截普通功能页，并显示“请在手机自带浏览器中打开”的提示；这是当前显式保护行为。`/healthz` 是开发中心菜单验证专用的例外路径。若未来实现菜单登录，应只放行一次性票据兑换端点。
- **公众号验证回调失败**：确认 URL 是 HTTPS 公网地址且路径为 `/auth/wechat/code/callback`，公众号 Token 与环境变量逐字符一致，选择明文 XML 模式。检查代理是否把 POST 正确转发到该服务。
- **二维码生成失败**：检查 AppID/AppSecret、公众号接口权限、access_token 获取错误和平台要求的 IP 白名单。不要在页面或日志输出 AppSecret。
- **收不到扫码或文本事件**：在开发中心观察是否出现其他有效事件；确认公众号配置的 URL 指向本服务。如果同一个公众号已由其他系统接收消息，需要先统一回调入口并做事件分发。
- **验证码无效**：确认用户扫的是当前网页上的二维码，并在同一浏览器页输入最新验证码；二维码十分钟、验证码五分钟过期，验证码只允许一次成功兑换，错误五次即失效。
- **找不到成员**：确认公众号身份已经绑定成员；若网站应用与公众号使用不同 OpenID，检查是否能取得匹配的 UnionID，以及二者是否关联到同一微信开放平台账号。
- **菜单测试未出现 VIEW**：确认菜单是“跳转网页”动作而非仅展开子菜单，保存并发布后等待生效；查看服务日志中的签名拒绝或请求错误。开发中心不保留签名无效请求，以免把未经验证的身份数据显示为可信事件。
- **轮换密钥**：同时更新公众号后台 Token 与 `FMLYSYS_WECHAT_OA_TOKEN`，重启服务，再通过后台验证回调。更新 AppSecret 后也需重启，让公众号 API 客户端使用新配置。

当前程序只处理登录所需的扫码/关注事件和“登录”文本，其它有效事件会确认接收但不做业务处理。启用开发者服务器前，应确认现有公众号自动回复、菜单事件或其他集成不会因单一消息回调地址被覆盖。
