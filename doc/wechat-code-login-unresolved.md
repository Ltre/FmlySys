# 微信验证码登录待解决事项

状态：**待真实公众号消息投递验证，暂不验收、暂不合并**  
更新日期：2026-10-05  
专用开发分支：`dev-2609A-step2-fake-wechat-qrlogin`

## 当前结论

用户实际测试新关注、重新关注和发送“登录”后都没有收到验证码；随后在开发中心检查，相关时段没有任何 `POST` 类型的“微信回调”记录。因此现有证据表明，这些真实消息没有到达当前 Go 进程。现阶段不能声称线上微信验证码登录已修好或可用。

用户确认公众号后台保存的消息推送 URL 为 `https://fmly.miku.us/auth/wechat/code/callback`，状态为启用。线上手工探测该地址时，带 `MicroMessenger/8.0` 的无签名 GET 和 POST 均返回 `403 invalid signature`。这是预期的无签名探测结果，说明请求现在能穿过微信浏览器拦截并到达应用签名校验；它不是公众号的真实签名请求，也不能证明微信事件投递成功。

本地代码的回调流程和中间件测试已通过：明文 XML 的 `subscribe`、`SCAN` 和文本 `登录` 会尝试生成验证码并用 XML 被动回复。公众号后台当前选择的消息加密模式尚未从用户提供的记录中确认。当前处理器只支持明文 XML，不支持安全/兼容模式的 `msg_signature` 校验和 `<Encrypt>` 解密。

## 后续排查步骤

1. 在一次受控测试中记录新关注和发送“登录”的精确时间，并确认开发中心查看的是实际处理请求的进程。诊断记录只保存在各进程内存中，最多 100 条；重启、多实例或看错进程都会造成列表没有对应记录。
2. 在公众号后台确认消息加密方式为**明文模式**、数据格式为 XML，保存后重新验证服务器配置。不要在工单或聊天中发送 Token、AppSecret 或 EncodingAESKey。
3. 以该时间检查 Cloudflare Security Events/WAF/Bot 事件和反向代理访问日志，确认 `GET`、`POST /auth/wechat/code/callback` 没有被质询、拦截、限流或改写。此路径应保留查询参数及 XML 正文，不应被缓存，也不应重定向。再核对源站访问日志和实例路由。开发中心没有 POST 时，应用不能提供被 Cloudflare 或代理丢弃的请求详情。
4. 下一次测试后导出该时段的“微信回调”原始 JSON 和“服务异常”记录，按下面的响应判断继续处理。

| 真实回调记录 | 判断与处理 |
| --- | --- |
| 没有 POST | 消息未到当前进程。继续查公众号服务器推送状态、Cloudflare/WAF、反向代理、源站防火墙、实际服务实例；不要改验证码生成逻辑来处理一个未到达应用的请求。 |
| POST 为 `403 invalid signature` | 请求已到应用但签名未通过。核对线上进程加载的 `FMLYSYS_WECHAT_OA_TOKEN` 与公众号后台 Token，并确认明文模式及服务器时间。 |
| 正文包含 `<Encrypt>`，或 query 使用加密签名参数 | 后台仍处于安全/兼容模式；当前实现不能解密。切换为明文模式后重新验证。 |
| POST 为 `200 success`，没有 XML 回复 | 查看原始 XML 是否为 `Event=subscribe`/`SCAN` 或 `Content=登录`。其它事件、文本以及无法解析的加密 XML不会发码。 |
| POST 返回验证码 XML，但手机没有收到 | 应用已生成回复；根据回调耗时、响应正文及公众号后台消息投递结果继续查被动回复限制和公众号会话状态。 |
| POST 返回“暂时无法生成登录验证码” | 事件已到处理器；检查同一实例的服务异常、数据库迁移 `000012_wechat_openid_login_codes.sql`、数据库写入和随机数错误。 |

## 验收条件

- 公众号后台服务器验证成功，实际带签名的回调 GET 原样返回 `echostr`。
- 新关注公众号后，开发中心出现真实 `subscribe` POST，手机收到含八位验证码的回复。
- 已关注用户发送“登录”后，开发中心出现真实文本 POST，手机收到含八位验证码的回复。
- 验证码可在 `/login/wechat-code` 成功兑换为已绑定成员会话，并且过期、重复使用和未绑定身份均按预期拒绝。
