## 32. 成员软删除、成员资料维护、后台快速记录处理与转账用途展示

日期：2026-08-24

### 32.1 成员删除统一改为零余额软删除

此前 `DeleteMemberSmart` 会根据成员是否被业务/审计记录引用，在“物理删除”和“软删除”之间选择。该规则会让一个没有历史引用的成员行真正消失，与本轮“后台删除成员永远只做标记删除”的要求冲突。

本轮把删除语义固定为：

```text
后台点击标记删除
→ 先进入与资金写入共用的串行 gate
→ 在同一个 SQLite transaction 中计算该成员当前公共资产代管余额
→ 余额 != 0：拒绝删除，成员及认证状态均不改变
→ 余额 == 0：members.is_del=1、status='deleted'
```

余额计算沿用当前完整账本口径，包含：

- 初始资产 / 资产新增 / 资产划出 / 财务调整；
- 成员间转入、转出；
- 使用该成员代管公共资产支付的消费；
- 该成员作为公共资产持有人支付的后续报销。

因此删除检查与系统实际显示的“持有资产”口径一致，并与并发资金写入串行，避免检查为 0 后同时又写入一笔资金变动。

删除成功时只撤销业务访问能力：

- 删除成员登录 session 与权限；
- 解绑微信身份并把原加入申请恢复为可重新申请状态；
- 撤销旧式 Passkey 认证状态；
- 对新的独立 Passkey login identity，删除关联的登录 session / ceremony，并把 `member_id` 解除关联，但保留独立身份及其凭据。

明确不删除、不隐藏：

```text
members 行本身
asset_events
public_expenses
holder_transfers
reimbursements
audit_logs
record_attachments / 历史凭证
```

`MembersForAccounting()` 继续把已删除成员带入历史账务计算，并显示为“姓名（已删除）”。因此成员被停用后，原有资金流水、审计操作记录及其成员姓名仍可追溯，不会因为后台删除动作从账簿中消失。

兼容旧入口的 `DeleteMemberSmart()` 也改为只代理上述软删除，不再存在 hard-delete 分支。

### 32.2 后台成员信息修改

后台“成员与权限”中每个成员增加“修改成员信息 / 标记删除”管理区，可修改：

- 成员姓名；
- 关系 / 备注。

服务端新增独立成员资料更新接口，规则：

- 姓名去除首尾空格后必填，最多 80 个 Unicode 字符；
- 关系 / 备注最多 160 个 Unicode 字符；
- 已标记删除的成员不能再修改资料；
- 修改前后值写入 `audit_logs`，动作类型为 `update/member`。

成员权限保存继续走原接口，成员资料与权限不混在同一写操作里。

### 32.3 后台处理前台快速记录

后台 `/admin` 新增“前台快速记录”区域，管理员能查看所有成员提交的快速记录，包括：

- 原记录人；
- 分类；
- 摘要；
- 提交时间；
- 原附件；
- draft / 已入库状态。

草稿提供“进行数据入库”，进入后台标准化页面。表单字段与前台保持同一套分类逻辑：

- 公共消费；
- 内部转账；
- 登记报销；
- 资产变动登记。

这里必须区分两个身份：

```text
原快速记录提交人 = 资金业务主体
后台 DevActorID   = 正式入库执行人 / 审计 actor
```

例如张三提交一条快速内部转账：后台选择“转给李四”时，正式流水仍是“张三 → 李四”，而不是“后台开发身份 → 李四”。公共消费的经手人、报销付款持有人、资产变动持有人也都继续是原快速记录提交人。

正式入库继续复用第 29 节的原子事务：

```text
创建正式资金记录
+ audit
+ 把 quick_money_note 附件归属迁移到正式记录
+ quick_money_notes 标记 standardized
→ 同一 transaction COMMIT
```

如果原记录成员已经被标记删除，则后台不能再以其名义生成新的资金流水；历史快速记录仍可查看。

### 32.4 后台内部转账流水补充“用途 / 事务”

Store 原有 `Transfers()` 已经查询并填充：

```text
Purpose
MatterTitle
```

问题只在后台表格没有展示。本轮后台增强脚本给“内部转账流水”增加“用途/事务”列：

```text
用途说明
事务：<关联事务标题>
```

没有填写时显示 `—`。数据通过受管理员认证保护的后台 JSON 接口读取，不改变账务表结构。

### 32.5 后台增强接入方式

为避免继续复制一份巨大的 `/admin` 模板，本轮新增 `WithAdminEnhancements` 外屚路由：

- `GET /admin  仍由既有后台 handler 生成主体页面，仅在成功 HTML 响应末尾注入 `admin-enhancements.js`；
- 成员资料编辑、软删除、快速记录读取/入库、内部转账补充数据使用独立 `/admin/...` 接口；
- 所有这些接口继续经过 `adminOnly`；
- 不新增数据库 migration。

这样现有资产、消费、转账、报销、权限和 Passkey 后台功能仍由原模板/handler 维护，新能力作为后台管理增强层接入。

### 32.6 回归测试与验证边界

本轮更新成员删除测试，覆盖：

1. 零余额且无业务引用的成员也只能软删除，成员行必须保留；
2. 非零代管余额时删除被拒绝，而且认证状态不能被提前撤销；
3. 余额归零后软删除，既有资产、消费和审计记录继续存在；
4. `MembersForAccounting()` 仍返回“（已删除）”成员；
5. 成员资料修改写入审计；
6. 系统开发身份仍不能删除自身。
